# ROS2 远程驾驶上位机通信格式

本文档面向编写 ROS 2 通信包或 WebSocket-ROS 2 桥接节点的开发者。
它描述当前 Qt 上位机已经实现的应用层协议。Qt 上位机不直接使用 ROS 2 DDS，
而是作为 WebSocket 客户端与 ROS 侧服务通信；ROS 包需要提供 WebSocket 服务端，
并负责将 JSON 转换为 ROS 2 topic、service 或自定义消息。

## 1. 传输层

- 协议：WebSocket
- 载荷：UTF-8 文本 JSON
- 消息边界：一条 WebSocket 文本消息对应一个完整 JSON 对象，不需要额外换行符
- 默认地址：`ws://127.0.0.1:8770`
- 地址可在 Qt 界面顶部修改
- 当前协议没有定义认证、加密或控制指令应答；生产环境如需安全传输，应使用 `wss://`
  并在桥接节点外围增加认证机制

连接成功后，Qt 会开始发送心跳；连接断开时停止心跳，并自动尝试每 2 秒重连。

## 2. 控制指令：Qt -> ROS WebSocket 服务端

每条控制消息的 `type` 固定为 `control`。实际发送的 JSON 包含以下字段：

| 字段 | JSON 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `type` | string | 是 | 固定为 `"control"` |
| `steer` | number | 是 | 转向指令，范围 `-1.0` 到 `1.0` |
| `throttle` | number | 是 | 油门指令，范围 `0.0` 到 `1.0` |
| `brake` | number | 是 | 刹车指令，范围 `0.0` 到 `1.0` |
| `gear` | integer | 是 | 档位。档位数值的具体含义由 ROS 包定义，`0` 通常表示空挡 |
| `mode` | string | 是 | `"manual"`（手动）或 `"replay"`（回放） |
| `enable` | boolean | 是 | `true` 表示允许执行控制；`false` 表示禁止驱动 |
| `timestamp` | integer | 是 | Qt 发送时填写的 Unix 时间戳，单位为毫秒 |
| `seq` | integer | 是 | Qt 端递增的控制序号，从 1 开始 |

示例：

```json
{
  "type": "control",
  "steer": 0.12,
  "throttle": 0.35,
  "brake": 0.0,
  "gear": 1,
  "mode": "manual",
  "enable": true,
  "timestamp": 1756800000123,
  "seq": 42
}
```

### 控制语义和安全要求

1. ROS 桥接节点应在执行前再次校验字段类型和数值范围。不要只依赖 Qt 端的限幅。
2. `enable == false` 时，车辆控制节点应进入安全状态，至少禁止油门；建议同时施加刹车。
3. 急停或停止时，Qt 发送的典型消息如下：

```json
{
  "type": "control",
  "steer": 0.0,
  "throttle": 0.0,
  "brake": 1.0,
  "gear": 0,
  "mode": "manual",
  "enable": false,
  "timestamp": 1756800000123,
  "seq": 43
}
```

4. 本地红灯状态会强制发送 `throttle: 0`、`brake: 1`、`enable: false`。
   ROS 侧仍应实现自己的安全仲裁和超时保护。
5. 手动控制通常每 50 ms 发送一次（约 20 Hz）；回放模式按回放文件中的 `t_ms` 调度，
   不应假设固定频率。
6. 当前 Qt 不等待控制应答。若 ROS 侧需要确认、拒绝或报错，可另行发送状态或日志消息，
   但 Qt 当前不会根据控制 ACK 改变控制状态。

## 3. 车辆状态：ROS WebSocket 服务端 -> Qt

推荐发送以下格式：

```json
{
  "type": "status",
  "x": 1.234,
  "y": 2.345,
  "yaw": 0.785,
  "speed": 0.80,
  "battery": 24.6,
  "traffic": "green"
}
```

字段说明：

| 字段 | JSON 类型 | 说明 |
| --- | --- | --- |
| `type` | string | 推荐为 `"status"` |
| `x` | number | 二维位置 X |
| `y` | number | 二维位置 Y |
| `yaw` | number | 航向角 |
| `speed` | number | 车辆速度 |
| `battery` | number | 电池电压；Qt 界面以 V 显示 |
| `traffic` | string | `"green"`、`"red"` 或 `"stop"` |

当前解析器也接受省略 `type` 但包含 `x` 字段的对象。数值字段缺失时 Qt 按 `0` 处理，
`traffic` 缺失时保持当前交通灯状态。建议 ROS 包始终发送完整字段，减少状态歧义。

协议代码不强制单位。建议 ROS 侧统一采用 SI 单位：位置为米、`yaw` 为弧度、速度为米/秒、
电池为伏特，并在 ROS 消息定义中保持一致。

`traffic` 取值不区分大小写，Qt 会转换为小写；收到 `red` 或 `stop` 时，界面切换到红灯并
禁止油门，收到 `green` 时恢复绿灯显示。

## 4. 心跳和延迟：双向

Qt 连接成功后每 1 秒发送一次：

```json
{
  "type": "ping",
  "timestamp": 1756800000123
}
```

ROS WebSocket 服务端应尽快原样返回时间戳：

```json
{
  "type": "pong",
  "timestamp": 1756800000123
}
```

Qt 根据 `pong.timestamp` 计算最近 5 次样本的平均单向延迟。缺少或无效的时间戳不会更新
延迟显示。服务端可以同时向多个客户端发送状态，但每个客户端的 `ping` 都应独立响应。

## 5. ROS 2 桥接节点实现建议

以下内容是实现建议，不是当前 Qt 已固定的 ROS 接口：

- 接收 `control` 后转换为车辆底盘所需的标准或自定义控制消息，例如 Ackermann、Twist
  或底盘专用消息。
- 将里程计转换为 `x`、`y`、`yaw`、`speed`；将电源状态转换为 `battery`。
- 如果交通灯由感知或规划节点提供，将其规范化为 `green`、`red`、`stop` 三种字符串。
- 在桥接节点实现控制超时：超过约定时间没有收到新的 `control`，应自动发送安全停止，
  不应继续保持上一条油门指令。
- 校验 `seq` 是否倒退或重复，并根据需要丢弃过期的 `timestamp`。
- ROS topic 名称、QoS、消息类型和坐标系（例如 `map` 或 `odom`）当前未在 Qt 项目中规定，
  应在 ROS 包自己的接口文档中明确。

## 6. 本地回放 JSON（非 WebSocket 消息）

Qt 支持加载一个 JSON 数组作为回放文件。数组元素必须是对象，`t_ms` 必须按非递减顺序
排列，单位为毫秒：

```json
[
  {"t_ms": 0, "steer": 0.0, "throttle": 0.2, "brake": 0.0, "gear": 1},
  {"t_ms": 1000, "steer": 0.3, "throttle": 0.2, "brake": 0.0, "gear": 1},
  {"t_ms": 2500, "steer": 0.0, "throttle": 0.0, "brake": 1.0, "gear": 0}
]
```

回放文件只在 Qt 本地读取；回放运行时，每个元素会被转换成第 2 节的 WebSocket `control`
消息，并自动设置 `mode: "replay"`、`enable: true`。回放结束后 Qt 会发送停止指令。

## 7. 最小兼容性检查清单

- [ ] WebSocket 服务端监听 `ws://127.0.0.1:8770`（或让用户在界面中配置实际地址）
- [ ] 能解析 UTF-8 JSON 文本消息
- [ ] 能处理 `type: "control"`、`type: "ping"`
- [ ] 对每个 `ping` 返回带相同 `timestamp` 的 `pong`
- [ ] 按完整字段发送 `type: "status"` 状态消息
- [ ] 对控制值、`enable`、时间戳和消息超时执行 ROS 侧安全校验
- [ ] 明确 ROS topic、消息类型、单位和坐标系的映射
